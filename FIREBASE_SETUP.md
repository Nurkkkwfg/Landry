# Настройка Firebase (Firestore) — бесплатно

1. https://console.firebase.google.com → **Add project** (Analytics не нужен).
2. **Build → Firestore Database → Create database**. Режим: *Production*; регион — ближайший (например `europe-west3`).
3. **Project settings → Service accounts → Generate new private key** — скачается JSON-файл.
4. Положите содержимое JSON **одной строкой** в переменную окружения `FIREBASE_CREDENTIALS`:
   - Render: *Environment → Add Environment Variable* (в git и в чат ключ не выкладывать!);
   - локально: `FIREBASE_CREDENTIALS_FILE=./serviceAccount.json` в `.env` (файл в `.gitignore`).
5. Правила Firestore можно оставить закрытыми (`allow read, write: if false;`) — бот ходит через сервисный аккаунт, правила его не касаются.
6. Перенос старых данных (если они есть): `python migrate_sqlite.py путь/к/laundry.db`.

## Лимиты бесплатного плана (Spark), ориентир — проверяйте актуальные в консоли
Чтения ~50 000/сутки, записи ~20 000/сутки, удаления ~20 000/сутки, хранилище 1 ГиБ. Для ~100 заказов в сутки хватает с запасом.

## Что изменилось по сравнению с SQLite
- Составные индексы не нужны: все запросы по равенству / одному полю.
- Номера заказов — через счётчик в транзакции (1, 2, 3…, не повторяются).
- Диалоги бота (FSM) хранятся в Firestore (`fsm`), старше 3 дней чистятся.
- Поиск по имени — по началу слова (плюс «содержит» среди активных заказов); по телефону — по последним 9 цифрам либо по началу номера.
- Бэкап: ночью в 03:00 (Бишкек) админам приходит `.json.gz`. `/backup full` — выгрузка всего. Восстановление — отправить файл с подписью `/restore` (с подтверждением, существующие записи перезаписываются, ничего не удаляется).

## Новое
- История статусов заказа (кнопка «📜 История»).
- Диспетчерам приходят уведомления о смене статуса (если диспетчеров нет — админам).
- Напоминания о зависших заказах (порог по статусам и рабочие часы — в `.env.example`).
- Авто-завершение смены курьера через `SHIFT_MAX_HOURS` (по умолчанию 14 ч).
