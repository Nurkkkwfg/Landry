# Бот прачечной (ковры, шторы)

Роли: **админ** (ID в `ADMIN_IDS`), **диспетчер**, **курьер**, **цех**.
Заказы нумеруются 1, 2, 3… Карточка: № / имя / номер / адрес.

## Запуск
1. Настройте Firebase (Firestore) по инструкции в [FIREBASE_SETUP.md](FIREBASE_SETUP.md).
2. `cp .env.example .env` → впишите `BOT_TOKEN`, `ADMIN_IDS` (через запятую) и `FIREBASE_CREDENTIALS` (или `FIREBASE_CREDENTIALS_FILE`).
3. `./run.sh` (Linux/macOS), `run.bat` (Windows) или `docker compose up -d --build`.
Данные хранятся в Firestore. Запускайте один экземпляр бота.

## Как работает
- Новый сотрудник пишет `/start` → админ получает кнопки выбора роли (👥 Сотрудники — смена роли/удаление).
- **Диспетчер/админ:** «➕ Новая заявка»: номер → имя → адрес (или сразу 3 строки: имя / номер / адрес). Знакомый номер подставляет имя и адрес.
  **Адрес:** пишете улицу и дом → бот ищет и присылает до 5 вариантов → вы выбираете точный → вводите подъезд/этаж/кв. Адрес и координаты фиксируются.
  Не нашёл? Напишите иначе, пришлите точку на карте (📎 → Геопозиция) или «Оставить как написал».
  Поиск: 2ГИС (если задан `DGIS_KEY`) → Photon → Nominatim, с повтором и кэшем.
- «📋 Заказы», «🔎 Поиск» (№, телефон, имя), ✏️ изменить (только пока заказ активен), ❌ отменить (кроме заказов в цехе), «📜 История» — все смены статуса.
- Диспетчеры получают уведомления о каждой смене статуса (если диспетчеров нет — админы).
- **Напоминания:** раз в 10 минут бот проверяет зависшие заказы и шлёт диспетчерам сводку; курьеру — про заказы у него на руках. Пороги — в `.env.example` (`REMIND_*`), только с 8:00 до 22:00 по Бишкеку.
- **Курьер:** «🟢 Начать смену» → «📍 Геопозиция» → задачи от ближних к дальним, без лимита; «🗺 2ГИС». Смена сама завершается через `SHIFT_MAX_HOURS` (14 ч).
  «✅ Забрал» → заказ у водителя → «🏭 Сдать в цех» (всё сразу). Готовые заказы: «🚚 Взял» → «✅ Доставил».
  Когда один курьер берёт заказ, у остальных карточка заменяется на «уже взят».
- **Цех:** «🧼 В цехе» или просто номер заказа → «📐 Замеры»: размеры ковров по строкам (3х4 / 4х5 …), затем сколько штор → «✅ Готово».

Статусы: 🆕 Новый → 🚗 У водителя → 🏭 В прачечной → ✅ Готов к доставке → 🚗 У водителя → 📦 Завершён (или ❌ Отменён).

## Render
Нужен тип **Background Worker** (бот работает постоянно). Диск больше не нужен — данные лежат в Firestore.
1. Выложите папку в GitHub (`.env` и ключи Firebase в репозиторий не попадают — они в `.gitignore`).
2. Render → New → Blueprint → выберите репозиторий (`render.yaml` настроит всё), задайте `BOT_TOKEN`, `ADMIN_IDS`, `FIREBASE_CREDENTIALS` (JSON ключа одной строкой), `DGIS_KEY` (необязательно).
   Вручную: Background Worker, build `pip install -r requirements.txt`, start `python main.py`.

## Перенос данных из SQLite
Если есть старая база: `python migrate_sqlite.py путь/к/laundry.db` (можно запускать повторно).

## Бэкап и восстановление
- Админу: кнопка «💾 Бэкап» или `/backup` — бот присылает файл `.json.gz` (сотрудники, активные заказы и всё за 60 дней); `/backup full` — выгрузка всего. Каждую ночь в 03:00 (Бишкек) копия приходит всем админам сама.
- Восстановить: админ отправляет файл боту с подписью `/restore` → бот показывает сводку и просит подтвердить; перед восстановлением присылает копию текущих данных. Записи с теми же номерами перезаписываются, остальные не удаляются.
